# c20 TileM 参数空间分析

## 1. Kernel 实际接收参数

| 参数 | 分类 | c20 取值 / 作用 |
|---|---|---|
| `B/M/N/K` | 固定输入 | `1/33/513/256` |
| dtype/layout | 固定输入 | 性能主对照为 FP16 `00`；正确性覆盖 FP16/BF16 和四布局 |
| `TileM` | 独立可调 | `{32, 64}` |
| `TileN/TileK` | 本轮固定 | `128/64`，隔离 M 切分的影响 |
| schedule/reduction/buffers | 本轮固定 | async / vector / 2 UB C buffers |
| `RowsPerLane` | 派生 | `TileM / 2` |
| `mGroups` | 派生 | `ceil(M / TileM)` |
| `launchBlocks` | 派生 | `min(B*mGroups, 20)` |
| workspace | 派生 | system workspace + per-lane async C cache + atomic output |

## 2. 约束来源

- MIX kernel 固定一个 AIC 配对两个 AIV，因此 `RowsPerLane=TileM/2`。
- FP16/BF16 Cube `baseM` 基本块最小为 16，所以当前框架下 `TileM>=32`。
- `TileM=16` 会导致 `RowsPerLane=8`，不符合 Cube 基本块约束，不进入上板候选集。
- `TileM=32/64` 均满足 L0/L1/UB 容量约束；这些是硬件容量门禁。
- key 121 中的 `TileM=64` 和提交阈值是软件经验值，可以搜索。

## 3. 算法使能

| 算法 | 结论 | 原因 |
|---|---|---|
| SWAT / 当前 Matmul API | 命中 | 通用回退路径，K=256 |
| FullLoad | 本轮不单独使能 | 当前主要问题是核数欠占用，先隔离 `TileM` 变量 |
| StreamK | 未命中 | K=256，远低于 StreamK 门槛 |
| split-N | 仅作历史对照 | key 130 五分片已测 144.846 us，同步与二次归约未摊薄 |

## 4. 候选解空间

| key | TileM | Rows/lane | M groups | blocks | 理论填充行数 | 主要 tradeoff |
|---:|---:|---:|---:|---:|---:|---|
| 121 | 64 | 32 | 1 | 1 | 64 | 少一个 task，但只用 1/20 AIC |
| 122 | 32 | 16 | 2 | 2 | 48 | 并行度翻倍且填充减少，但多一个 task 并重复读 B |

性能决策只根据同机 p50/p95 和 msprof Task Duration/pipe 数据，不根据理论评分直接修改默认 policy。
